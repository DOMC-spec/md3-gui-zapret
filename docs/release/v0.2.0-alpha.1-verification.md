## Ошибка первого CI и исправление

Первый [CI коммита 85ee799](https://github.com/MiffedFive/md3-gui-zapret/actions/runs/39138960685) прошёл Release build, Core 20/20, Game Filter, все 44 CMD-сравнения стратегий и модельные служебные/пробные сценарии. Он упал при инертном нативном пробном сеансе с `Access is denied`. Пакет не публиковался. Ошибка проверки cleanup скрывала, на каком исходном чтении возник отказ.

Для локализации использован отдельный `.scratch/native-observe-probe`, вызывающий настоящий `WindowsManualProcessBackend` с собственными инертными sc/winws. Короткие sc завершаются во время наблюдения; winws остаётся живым. На второй попытке получили Win32Exception 5 из `Identity` при перечислении job. Повтор с временным `[DEBUG-native-exit]` показал `wait=258`, затем `wait250=0`: чтение идентичности уже недоступно, но процесс становится signaled немного позднее. Две диагностические попытки дали тот же результат. Это подтверждённая причина данного воспроизведения; прежние несвязанные Access denied не объявляются причинно устранёнными.

Регрессия добавлена на существующей системной границе `IManualProcessBackend`: `--native-observation-only` запускает 12 собственных jobs с 20 короткими helpers, подтверждает идентичность живого winws, её стабильность и завершение job. Версия без периода жизни процесса не воспроизвела ошибку; восстановление двухсекундного периода из минимального воспроизводителя дало красный результат на исходном коде. Регрессия включена также в полный Guard. Служба, драйвер и TCP в этих сценариях не меняются.

Исправление ограничено чтением идентичности нового члена job: при Win32Exception выполняется ожидание того же дескриптора до 250 мс; пропуск разрешён только при подтверждённом завершении. Если процесс жив, исходная ошибка сохраняется. Нет обхода прав, доверия имени/PID вместо идентичности, завершения сторонних процессов или подавления ошибок живых процессов. Диагностический код удалён.

Сигнализированный дескриптор означает завершение процесса согласно [документации Microsoft](https://learn.microsoft.com/en-us/windows/win32/procthread/terminating-a-process). Конкретная гонка и 250 мс подтверждены локальным воспроизводителем, а не выводятся из одной документации.

Журналы красного воспроизведения и зелёных проверок хранятся в игнорируемой папке `artifacts/release-v0.2.0-alpha.1/`. Полный повтор CI и опубликованные SHA-256 фиксируются в GitHub Release только после успешного прогона. Нативная выпускная матрица остаётся открытой.

# Кандидат оболочки для Flowseal 1.10.3

Статус: **альфа, выпускная приёмка не завершена**. Сборка кандидата проверяет код и модельные сценарии; для готового выпуска требуется отдельный протокол на выделенной Windows x64. Проверка настоящих служб, драйвера, TCP и аппаратной доступности пока не выполнена. Поддержка 1.10.2 не заявляется.

По прямому решению пользователя предварительная альфа v0.2.0-alpha.1 может публиковаться для ограниченного тестирования до завершения нативной приёмки. Это отдельный статус распространения, он не закрывает задачу 12 и не меняет незаполненные результаты ниже. [Возможности и ограничения альфы](https://github.com/MiffedFive/md3-gui-zapret/blob/v0.2.0-alpha.1/docs/release/v0.2.0-alpha.1.md).

## Сборка и состав

На Windows x64 установите PowerShell 7, Git и точный .NET SDK из `global.json` (8.0.409), включая .NET 8 targeting packs и Windows Desktop/WPF. Отдельные workloads не нужны. Нужен доступ к NuGet для первого восстановления пакетов. Пользователю автономного EXE отдельный .NET Runtime не требуется. Поставка Flowseal в EXE не включена.

Из чистого checkout зафиксированного коммита выполните:

```powershell
pwsh -NoProfile -File tools/Build-Candidate.ps1
```

Скрипт использует `restore --locked-mode`, Release-сборку solution, Core, полный Guard и полный WPF smoke в обеих темах, затем `publish --no-build`. Guard и WPF идут последовательно. При ошибке упаковка не выполняется; журнал остаётся в отдельной папке запуска `artifacts/candidate-<id>/checks`. Обычный CI выполняет этот же скрипт на Windows 2022. Удалённый результат CI нужно проверять отдельно после публикации изменений.

Успешный запуск создаёт ZIP с автономным `Zapret.Configurator.exe`, README, лицензией, этим протоколом, эталонным манифестом, `build.json` и `SHA256SUMS.txt`. Рядом находятся контрольная сумма ZIP и журналы/снимки проверок. `build.json` фиксирует исходный коммит, SDK, SHA-256 EXE, происхождение Flowseal и незавершённую приёмку. Воспроизводимость означает закреплённые входы и последовательность сборки; побайтовое совпадение ZIP (время упаковки) не обещается. Перед распространением сверяйте SHA-256 с протоколом именно этой сборки. Кандидат автоматически не публикуется.

Эталон: Flowseal commit `865da4f4c3659523bf79bc6edf0446e7d7969614`, SHA-256 исходного архива `244314ae1c24538a0d751601da8e0c925c843371eec4456eb15f14c4fd6b7058`. Точные хэши управляющих файлов находятся в `flowseal-1.10.3.json` внутри пакета и в `src/Zapret.Core/Compatibility/flowseal-1.10.3.json` репозитория. Изменяемая main не служит эталоном. Подробнее: [контракт](../compatibility/flowseal-1.10.3.md) в репозитории.

## Возможности и маршрут пользователя

Через GUI доступны выбор и проверка поставки, выбор стратегии, пробный запуск, установка/замена автозапуска, отдельные запуск/остановка/удаление своей службы, Game Filter с TCP/UDP-диапазонами, добавление сайтов и исключений, расширенный редактор списков, обновление наблюдаемого состояния и восстановление незавершённой операции. Есть светлая/тёмная тема, видимый фокус и уменьшение движения. Предварительная проверка объясняет отказы до изменения службы.

Маршрут приёмки: открыть EXE → выбрать поставку → проверить готовность → выбрать стратегию → попробовать → завершить пробный сеанс → проверить действие → включить при загрузке Windows → настроить Game Filter и списки → прочитать результат и наблюдаемое состояние → закрыть и снова открыть GUI → восстановить незавершённую операцию в соответствующем сценарии. Терминал пользователю для этого маршрута не нужен; команды ниже нужны испытателю для независимого сбора доказательств.

Тесты Flowseal, обновления, IPSet и диагностика через GUI **не реализованы** и остаются последующим этапом. Запуск службы и HTTP-ответ не доказывают воспроизведение видео или голосовое соединение. Наличие нужных bin-файлов не доказывает подлинность их содержимого; используйте официальный архив с указанным хэшем. Для выполнения сохраняются ограничения путей из контракта; чтение папки с кириллицей или OneDrive не обещает успешный запуск BAT.

## Отдельный выпускной прогон в выделенной Windows

Этот прогон проводится вручную после обычного CI и не запускается `Build-Candidate.ps1`. Рабочий компьютер разработчика для него не используется. Нужна выделенная Windows/VM с правами администратора, восстановимым снимком, официальной распакованной поставкой 1.10.3, эталонным архивом и пакетом кандидата. Для аппаратного DPI нужна конфигурация с двумя разными масштабами; для screen reader фиксируются его название и версия. Если этих условий нет, соответствующий результат остаётся «не проверено».

До испытания запишите версию/сборку Windows, архитектуру, способ виртуализации, SHA-256 ZIP/EXE, `sourceCommit` из `build.json`, хэш Flowseal, пути, исходные файлы настроек/списков, состояние службы zapret и WinDivert, `netsh int tcp show global`. Снимок VM должен включать всё это состояние. Не выполняйте широкое удаление сторонних служб ради очистки.

Для каждой строки стратегий ниже и каждого из двух режимов Game Filter:

1. Восстановите один базовый снимок VM, выберите режим (отсутствующий флаг / `mode=all`, `tcp=2000-3000`, `udp=4000,5000-6000`). Зафиксируйте начальные байты всех списков и настроек, конфигурацию/состояние службы, драйвера и TCP.
2. Пройдите GUI-маршрут пробного сеанса и автозапуска. Сохраните снимки результата и наблюдаемого состояния, созданные списки/флаг, аргументы winws, `sc.exe qc zapret`, `sc.exe queryex zapret`, состояние драйвера и TCP. Проверьте завершение пробного процесса и возврат исходной службы.
3. Снова восстановите тот же снимок и тот же режим. Выполните штатный пробный BAT и установку той же стратегии через `service.bat`. Соберите такой же набор данных. Не сравнивайте второй запуск с остатками первого.
4. Сопоставьте подготовку, упорядоченные аргументы (включая повторы), регистрацию и фактическое состояние, TCP и файлы. Допустимые различия: путь корня, PID/время, служебный маркер GUI; источник всех прочих различий должен быть объяснён. Не нормализуйте сами порты или порядок фильтров.
5. Запишите PASS/FAIL с путями к обоим наборам доказательств; при сбое сохраните исходное состояние и текст ошибки. Не заменяйте пропуск предположением об эквивалентности.

## Системные и пользовательские сценарии

Для каждой строки сохраните исходный снимок, шаги, ожидаемый/наблюдаемый результат, журналы, снимки GUI и итог PASS/FAIL/не проверено. Все строки сейчас **не проверены на выделенной Windows**.

| Сценарий | Что должно быть подтверждено |
| --- | --- |
| TCP: timestamps исходно выключены | Подготовка включает timestamps до замены службы; сравнить со штатным BAT; записать отдельный результат |
| TCP: timestamps исходно включены | Повторная подготовка сохраняет включённое состояние и совпадает со штатным BAT; записать отдельный результат |
| TCP: отказ изменения timestamps | Понятный отказ до замены службы, прежняя конфигурация/состояние сохранены; отдельный результат ошибки |
| Game Filter: флага нет | Чтение и подготовка совпадают с BAT 1.10.3; отдельный результат |
| Game Filter: пустой флаг | Чтение и подготовка совпадают с BAT 1.10.3; отдельный результат |
| Game Filter: all | Чтение, запись и TCP/UDP-диапазоны совпадают с BAT; отдельный результат |
| Game Filter: tcp | Чтение, запись и только TCP-диапазон совпадают с BAT; отдельный результат |
| Game Filter: udp | Чтение, запись и только UDP-диапазон совпадают с BAT; отдельный результат |
| Game Filter: неизвестное содержимое | Чтение трактуется как у BAT 1.10.3; GUI сохраняет только штатное значение; отдельный результат |
| Отсутствующая / своя Running / своя Stopped | Пробный сеанс, установка/замена, Start/Stop/Delete; тип запуска и исходное состояние возвращаются согласно действию |
| Сторонняя и неизвестная служба/процесс, общий драйвер | Отказ без изменения чужой установки; широкое завершение winws и остановка общего драйвера отсутствуют |
| Ошибка подготовки, Stop/Delete/Create/Start, тайм-аут | Понятная ошибка, наблюдаемое состояние и результат восстановления; при внешнем вмешательстве безопасный отказ |
| Принудительное закрытие GUI на каждом этапе операции и пробного сеанса | Новый GUI обнаруживает защищённый журнал HKLM, восстанавливает своё состояние; повтор не перезапускает службу; повреждение/чужая правка блокирует восстановление |
| Второй GUI и внешний BAT/SCM | Межпроцессная блокировка; внешние действия обнаруживаются, не перезаписываются |
| Списки и Game Filter | Добавление/исключение домена и IDN, режимы/диапазоны, BOM/backup, внешняя правка, сохранение и перечитывание; итог виден в GUI |
| Пути | ASCII с пробелами; чтение кириллицы/OneDrive; отказ выполнения неподдерживаемых CMD-символов и слишком длинного пути с объяснением |
| Работающий winws завершается извне; служба меняется извне | GUI обновляет реальное состояние независимо от выбранной стратегии; выбор не выдаётся за работающую конфигурацию |
| Ранний выход winws, отделение через start, конфликт со службой, обычное закрытие GUI | Наблюдается свой процесс; возврат службы и завершение пробного сеанса согласованы с контрактом; отдельные результаты |
| Изменённая стратегия / service.bat / новая версия со старым номером | Затронутая возможность обозначена непроверенной, отказ до частичного выполнения; отдельные результаты |
| Полный маршрут без терминала в обеих темах | Выбор → пробный запуск/автозапуск → настройки → результат → восстановление; без обязательного командного шага пользователя |
| Физическая клавиатура | Tab/Shift+Tab, Enter/Space, раскрытия, все вкладки и действия, прокрутка, видимый фокус, отсутствие ловушек |
| Конкретный screen reader | Имена/состояния элементов, однократное чтение результатов/ошибок, отсутствие повторов при фоновом обновлении |
| Разные DPI/масштаб 100–200%, минимальное окно | Перенос между мониторами, читаемые статусы, доступность действий и прокрутки; обе темы и уменьшение движения |
| Видео / голос | Отдельные пользовательские действия, сервис/время/сеть и результат; не выводить успех из состояния службы или HTTP |

После каждого нативного прогона испытатель восстанавливает базовый снимок VM и повторно фиксирует `netsh int tcp show global`, службы, драйвер и байты настроек/списков: исходное состояние, включая TCP timestamps, должно быть восстановлено. Это очистка тестовой среды. Оболочка по контракту не отменяет успешно включённые timestamps при последующем отказе операции; такой результат сначала фиксируется, а затем среда восстанавливается снимком.

## Решение о выпуске

К протоколу приложите `build.json`, SHA-256, результаты обычного CI, 44 пары сравнений, системную матрицу и аппаратные проверки. При обновлении EXE его приёмка проводится заново. Испытатель указывает имя, дату, среду и открытые ограничения. Только после подтверждения критериев задачи 12 можно менять статус с кандидата на проверенный выпуск; пустые ячейки и непроверенные зависимости 03–07/11 не означают успех. Публикация требует отдельного поручения.

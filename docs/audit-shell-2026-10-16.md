# Проверка проекта как графической оболочки Flowseal

Дата: 16 октября 2026 года. Этот документ заменяет продуктовые выводы [первоначальной проверки](audit-2026-10-16.md), сохраняя её технические свидетельства и ограничения.

## Замысел и способ проверки

Программа предоставляет людям, которым некомфортна командная строка, графический доступ к конфигурациям и действиям zapret-discord-youtube от Flowseal. Целевой стиль — Material Design 3 Expressive. Поэтому критерий качества — соответствие исходным действиям поставки и понятность сценария, а не наличие самостоятельной системы управления обходом.

Повторно сопоставлены локальные исходники GUI и Core, BAT поставки 1.10.2, документация, тесты и workflow. Прочитан официальный [README Flowseal](https://github.com/Flowseal/zapret-discord-youtube#readme): он различает ручной запуск стратегии и установку службы для автозапуска, а также перечисляет служебные действия. Удалённая main — изменяемый источник контекста; это не доказательство совместимости с будущими релизами. Строки ниже относятся к локальным файлам.

Службы и сетевые настройки не изменялись, winws не запускался. Новый визуальный прогон и пользовательское тестирование не выполнялись. Полный набор .NET 8 тестов ранее не запустился из-за отсутствующего targeting pack; исправление только документов не меняет этого ограничения. Продуктовые пробелы отделены от подтверждённых расхождений исходников и рисков совместимости.

## Главный вывод

Сейчас реализован частичный графический конфигуратор службы: он извлекает аргументы из BAT собственным парсером и самостоятельно выполняет sc create/start/delete. Для оболочки Flowseal наиболее значимый риск — различие поведения GUI и исходного действия при одинаковом выборе пользователя. Уже найдены пропущенная подготовка TCP и несовпадение обработки некоторых состояний Game Filter.

Решение не сводится к скрытому запуску всех BAT: меню, pause, выбор по номеру и побочные действия требуют адаптации. Нужен ограниченный слой интеграции, проверяемый на соответствие поддерживаемой версии поставки. Его точный механизм в рамках этой проверки не выбирался.

## Приоритетные слабые места

### 1. P1: подготовка запуска отличается от Flowseal

**Подтверждённое расхождение.** general.bat:6 вызывает service.bat status_zapret; service.bat:5–8,134–136 включает TCP timestamps. Установка службы через BAT также вызывает tcp_enable на строке 347. GUI в src/Zapret.Gui/Services/ZapretService.cs:95–125 этого не делает.

11 из 22 локальных стратегий используют --dpi-desync-fooling=ts, например general (ALT).bat:19–20. На компьютере с выключенными timestamps GUI и BAT готовят разное окружение. Фактическое влияние на обход в конкретной сети не проверялось, но эквивалентность действий уже нарушена.

**Направление:** описать подготовку действия поддерживаемой поставки и обеспечить её выполнение через интеграцию. Если действие меняет системную настройку, графический сценарий должен объяснять её назначение и результат; проверка не выполняла это изменение.

### 2. P2: Game Filter имеет две разные трактовки

**Подтверждённое расхождение для некоторых состояний файла.** src/Zapret.Core/PresetParser.cs:78–104 самостоятельно читает game_filter.enabled. При отсутствии файла и явных all/tcp/udp поведение соответствует локальному service.bat:730–762. Однако пустой файл GUI трактует как all, BAT 1.10.2 — как udp. Неизвестное значение GUI трактует как disabled, BAT — как udp. GUI также понимает собственный формат mode= и диапазоны, которого эта версия BAT не читает как аналогичные настройки.

В проверенной поставке флага нет, поэтому текущий режим disabled совпадает; это не утверждение, что у пользователя сейчас включены другие порты. Существующий Core-тест проверяет формат mode=udp с диапазонами вместо соответствия формату BAT.

**Направление:** единый контракт состояния с выбранной версией Flowseal; тесты соответствия для отсутствующего, пустого, all/tcp/udp и неизвестного содержимого. Отдельно определить поддержку старых форматов, не подменяя семантику версии молча.

### 3. P1: обновление Flowseal может изменить смысл запуска незаметно для GUI

**Архитектурный риск с текущим примером из пункта 1.** PresetParser.cs:41–54 пропускает нераспознанные команды и вызовы подготовки, извлекая запуск winws. Новая обязательная подготовка через call может остаться незамеченной. Проверка неизвестных переменных не защищает от пропущенного действия.

**Направление:** обозначать поддерживаемую версию или набор возможностей поставки; проверять соответствие действий, а не только возможность извлечь аргументы. Неподдерживаемая конструкция должна давать понятное ограничение до изменения службы. Собственный парсер — адаптер ограниченного формата, а не обещание поддержки произвольного BAT.

### 4. P2: ручной запуск и автозапуск не представлены разными действиями

**Пробел сценария.** MainWindow.xaml:177–181 предоставляет «Остановить и удалить» и «Применить и запустить». ZapretService.cs:114–117 при применении всегда создаёт службу с start=auto. Отдельного ручного запуска конфигурации в GUI нет, хотя поставка Flowseal разделяет general*.bat и Install Service.

Для новичка «запустить» не обязательно означает «включить при каждой загрузке Windows». Удаление службы также не заменяет отдельный сценарий временной остановки.

**Направление:** различить проверочный ручной запуск и включение автозапуска, объяснять последствие кнопки до действия. Наличие каждого сценария в первой версии ещё не утверждено; текущая неполнота должна быть явной.

### 5. P2: часть действий отправляет пользователя обратно в консоль

**Пробел графического покрытия.** README прямо отправляет изменять Game Filter через service.bat. MainWindow.xaml содержит только вкладки службы и списков; тесты, Game Filter, IPSet, обновления и другие действия не представлены. Считать каждый пункт обязательным для первой версии пока нельзя, но постоянное исключение этих функций противоречило бы замыслу полной графической работы с выбранными возможностями поставки.

**Направление:** составить явную карту «действие Flowseal → сценарий GUI → поддерживаемая версия → проверка результата» и выбрать минимальный законченный пользовательский маршрут. Не создавать собственную альтернативную сетевую диагностику ради заполнения экрана.

### 6. P1: ошибка оболочки оставляет пользователя без прежней работы

**Подтверждённый путь ошибки из исходников.** ZapretService.cs:114–121 удаляет прежнюю службу до проверки успешного запуска новой, восстановления нет. На строках 62–83 удаление завершает все процессы winws по имени и останавливает общий WinDivert без подтверждения принадлежности. Наличие подобного поведения в BAT не делает его подходящим для прозрачного графического действия.

**Направление:** сохранить ранее согласованные проверки принадлежности, восстановления и конфликтов, применив их вокруг выбранного способа интеграции. Интерфейс должен объяснять, что именно осталось работающим после ошибки. Не перезаписывать обнаруженные сторонние изменения ради восстановления.

### 7. P2: пользователь должен разбираться в файлах и технических ошибках

**Наблюдение по исходникам интерфейса, без пользовательского теста.** MainWindow.xaml:76–81 показывает стратегию/пресет как имя файла; строки 117–143 требуют выбрать файл списка, открыть его и редактировать текст. MainViewModel.cs:65 выводит ex.Message; ошибки службы могут содержать sc и код, а сообщения предлагают проверять службы и журнал Windows.

Редактор файлов полезен как расширенный режим, но не завершает путь новичка «добавить сайт», «исключить сайт», «почему не запустилось». HostlistStore.Discover рекурсивно показывает list*.txt без связи с активной стратегией; пользователь может изменить список, который она не использует.

**Направление:** понятные названия действий и назначения списков, связь со стратегией, ошибка с причиной и доступным следующим шагом. Технические детали сохранять в подробностях или журнале.

### 8. P2: подготовка поставки остаётся ручной и проверяется частично

**Текущее ограничение.** MainViewModel.cs:15 фиксирует папку по расположению EXE; строки 100–102 при ошибке предлагают переместить его рядом с service.bat. При применении проверяются winws и упомянутые файлы, но готовность всей поставки и её версия явно не устанавливаются. Выбора другой папки нет.

**Направление:** понятный сценарий обнаружения или выбора поставки с объяснением отсутствующих компонентов и поддержки версии. Выбор папки — предлагаемое улучшение, а не уже согласованная обязательная функция первой версии.

### 9. P2: состояние может устареть после действий через BAT

**Подтверждено чтением кода.** MainViewModel.cs:57,83–103,114–115,130–131 обновляет состояние при инициализации, ручном обновлении и собственных операциях. Автоматической синхронизации внешних изменений нет. При совместном использовании GUI и BAT показанная стратегия и состояние могут оставаться прежними до обновления.

**Направление:** обновлять состояние в подходящие моменты, например при возврате в окно, и повторно проверять перед действием. Различать выбранную стратегию, зарегистрированную и реально работающую; при неизвестном состоянии не показывать уверенный успех.

### 10. P2: проверяется парсер и оформление, но не эквивалентность оболочки

**Пробел проверок.** tests/Zapret.Core.Tests/Program.cs для --upstream проверяет наличие разобранных аргументов, а не подготовку и результат запуска. .github/workflows/build.yml не передаёт upstream-набор и выполняет один светлый smoke-сценарий. Интеграционные проверки службы описаны вручную. В первоначальной проверке также найден приём --new&rem и других слитных операторов, который текущий отрицательный тест с пробелами не покрывает.

**Направление:** фиксированный набор сценариев поддерживаемой поставки, соответствие переменных и подготовки, модели результатов действий, интеграция службы в тестовой Windows и пользовательские маршруты. Полноценный запуск этих проверок здесь не выполнялся.

### 11. P2: Expressive пока является целью, а не подтверждённым свойством GUI

**Наблюдение по реализации.** M3Theme.cs и M3Controls.xaml задают базовую схему, типографику и стили MD3. Собственной системы Expressive-переходов и движения в исходниках не найдено; отсутствие таких деклараций не доказывает отсутствие всех анимаций библиотечных компонентов. Существующий дизайн-документ описывал базовый MD3.

Официальные [материалы M3](https://m3.material.io/get-started) включают в Expressive обновлённые компоненты, типографику, формы и [систему движения](https://m3.material.io/styles/motion/overview/how-it-works). Наличие фиолетовой темы и скруглений не является достаточной проверкой соответствия. Внешний вид не оценивался новым рендером.

**Направление:** проектировать Expressive вокруг основных действий оболочки, состояний и обратной связи, затем проверять реальные экраны, клавиатуру, масштабирование и уменьшение движения. Не заявлять достигнутое соответствие заранее.

## Что изменилось относительно первой проверки

| Прежняя оценка | Пересмотр |
| --- | --- |
| Самостоятельный конфигуратор службы | Частичная реализация графической оболочки; главное — верность действиям Flowseal |
| Постоянно исключить тесты, обновления и Game Filter | Пока не реализованы; охват GUI требует выбора, постоянный запрет снят |
| Расширять собственную логику управления как основу | Сначала определить ограниченную интеграцию и проверки соответствия |
| Ошибки внешних скриптов как непосредственные дефекты GUI | Ограничения интеграции при подключении соответствующего действия |
| Базовый MD3 как завершённый дизайн | Текущая основа; Expressive — целевое оформление |

Сохраняются актуальными отсутствие восстановления, широкое завершение winws, риск одновременных действий и неполная проверка BAT. Создание отсутствующих пользовательских списков уже реализовано в ZapretService.cs:103–110 — повторно предлагать его как отсутствующую функцию неверно.

Ошибки обновления IPSet, TLS-классификации, выбора лучшего теста, восстановления после DPI-теста и удаления GoodbyeDPI остаются наблюдениями о локальных внешних инструментах из исторического отчёта. Сейчас GUI эти операции не вызывает. Если их подключать, нужно показать ограничения результата и учесть побочные действия; автоматически приписывать их текущему GUI нельзя.

## Рекомендуемая очередность

1. Определить контракт интеграции с локальной 1.10.2 и покрытие действий. Сначала устранить различия подготовки и Game Filter; проверить более новые версии отдельно.
2. Обеспечить надёжность изменения службы и совместной работы с BAT без вмешательства в сторонние установки.
3. Сделать понятным законченный путь пользователя: готовность поставки → выбор → ручной запуск или автозапуск → проверенный результат → следующий шаг при ошибке.
4. Развивать Expressive и графическое покрытие следующих действий вместе с проверками соответствия.

Это рекомендации по результатам проверки. Код приложения, скрипты Flowseal, службы и настройки системы в этой работе не изменялись. Точный механизм адаптера и набор первой версии остаются открытыми техническими и продуктовыми решениями; новое интервью или реализация не подменяют прямо запрошенный пересмотр документов.

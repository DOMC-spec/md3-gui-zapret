## Поведение

До подготовки замены автозапуска или пробного сеанса сохраняются исходные конфигурация, состояние, процесс и метаданные восстановления службы, выбранная поставка/стратегия, отпечатки файлов и идентификатор операции. Перед каждой Stop/Delete/Create/Start сначала сохраняются намерение, ожидаемый снимок и разрешённый результат. Успешное наблюдение сохраняет точный новый снимок, включая идентичность процесса. Пробный сеанс также сохраняет запуск и наблюдаемый процесс; восстановление никогда не завершает процесс по записанному PID.

Журнал один на машину, как и служба и её mutex. Производственное хранение — двоичное значение `OperationV1` в 64-битном `HKLM\SOFTWARE\ZapretGui.Recovery`. Ключ создаётся с защищённой DACL и владельцем Administrators; полный доступ только SYSTEM/Administrators. Существующий владелец и точная DACL проверяются при каждом чтении/записи; пользовательский JSON из папки поставки не является источником команд восстановления. Формат версионирован, ограничен 1 МиБ и содержит SHA-256 для обнаружения повреждения. Контрольная сумма не заменяет ACL.

Каждая запись сохраняется целиком одним значением и подтверждается явным RegFlushKey и перечитыванием до команды Windows. Механизмы сверены с [Microsoft: создание защищённых объектов](https://learn.microsoft.com/en-us/windows/win32/secauthz/security-descriptors-for-new-objects) и [запись реестра на диск](https://learn.microsoft.com/en-us/windows/win32/sysinfo/opening-creating-and-closing-keys). RegFlushKey применяется только на этапах изменения, не в цикле наблюдения пробного процесса. Завершение оставляет запись Completed; новая операция может заменить только завершённую. Повреждённая/недоступная запись блокирует новые изменения.

После открытия GUI читает журнал и SCM под общей блокировкой. Живая операция другого экземпляра не объявляется прерванной. При обнаружении прерванной операции показаны её вид, этап и причина; отдельные кнопки выбирают сохранённую поставку и запрашивают восстановление. Сама загрузка окна не меняет службу. На время незавершённой операции блокируются новые действия службы, пробный запуск и сохранение списков; чтение состояния и смена поставки остаются доступны.

Восстановление заново сверяет журнал, принадлежность, полный исходный профиль, текущий процесс, конфигурацию и файлы. Допускаются точный ожидаемый снимок либо результат конкретной сохранённой команды. Изменение PID/времени создания после уже сохранённого Running, чужая или неизвестная принадлежность, изменения конфигурации/маркера/файлов прекращают восстановление. Внешние BAT не участвуют в mutex: неразличимые побитно совпадающие переходы в окне команды невозможно отличить от её собственного результата; гарантируется отказ на обнаруженные изменения.

Созданная запись удаляется только при подтверждённом совпадении с Desired и маркером данной операции. Исходно Running возвращается с запуском, Stopped — без запуска, Missing — без регистрации. Повторный вызов после Completed ничего не перезапускает. При новой аварии в ходе восстановления очередное намерение сохраняется тем же механизмом. Неизвестное или частично инициализированное создание Windows без подтверждённого маркера автоматически не удаляется: показан конфликт и необходимость ручной проверки.

Если авария произошла во время Preparing, служба должна совпасть с исходным снимком; запись закрывается без повторного выполнения BAT или сетевых команд. Подготовленные списки, пустые настройки отключённого Game Filter и включённые TCP timestamps сохраняются согласно задачам 04–06. Служба не пересоздаётся при обнаруженном внешнем изменении. Восстановление не требует фонового агента, автозапуска GUI или повторного запуска стратегии.

## Автопроверки

Согласованная граница TDD — GUI → адаптер с заменой системных SCM, хранения журнала и процесса. Производственный codec используется и в файловом fixture. Хранилище fixture делает Flush(true) и атомарную замену; это не доказательство ACL/RegFlushKey настоящего HKLM.

- Красный тест запрета изменений при недоступном журнале сначала получил Success; после реализации ни подготовка, ни SCM не вызываются.
- Реальные дочерние тестовые процессы принудительно завершаются после Preparing, перед Stop и после Stop/Delete/Create/Start, остановки службы для пробного режима, Launch и ManualActive. Новый адаптер читает сохранённый файл и восстанавливает исходные Running/Stopped/Missing; повторное обращение не меняет уже восстановленное состояние.
- Внешние изменения конфигурации, процесса и списков, повреждённая запись блокируют восстановление и новые изменения, сохраняя фактическое состояние. Отдельный красный тест выявил необходимость перепроверять текущую принадлежность даже при точном совпадении с записанным снимком; исправлено.
- Нативный инертный сценарий задачи 06 завершает только GUI-владельца job, сохраняя дескриптор наблюдаемого инертного winws для проверки его завершения ядром. Затем новый адаптер восстанавливает файловую модель службы. Настоящие служба, драйвер, TCP, winws и HKLM-журнал рабочего компьютера не изменяются.
- WPF: обнаружение незавершённой операции, явное действие восстановления, запрет новых действий, фактическое Running после возврата, сохранение конфликта и окна. Первый тест упал из-за отсутствующей команды; после реализации прошёл.
- Core — 20/20; сборка solution с `-m:1 -p:UseSharedCompilation=false --no-restore` без ошибок. NU1900 сообщает недоступность индекса NuGet для аудита пакетов. WPF светлой/тёмной тем прошёл, `artifacts/07-light.png`, `artifacts/07-dark.png`.

Полный Guard завершился с кодом 0: паритет всех 22 стратегий с исходным CMD (обычные и пользовательские диапазоны), замена/управление/пробный запуск, нативный инертный Job и все аварийные сценарии 07. Дополнительный WPF preview с незавершённой операцией прошёл в светлой и тёмной темах, включая минимальное окно: `artifacts/07-recovery-light.png`, `artifacts/07-recovery-dark.png`; изображения просмотрены, предупреждение и кнопка восстановления видны, перекрытий нет.

## Открытая приёмка Windows

Выделенная VM не предоставлена. Реальные SCM/драйвер/TCP и защищённый HKLM-журнал остаются непроверенными в выделенной Windows. Требуется проверить создание/проверку ACL, durable flush, отказ доступа и повреждение, аварии между внутренними шагами CreateService/метаданных, длинные команды, восстановление после повторной аварии и отсутствие вмешательства в сторонние установки. Неопознаваемая частичная регистрация остаётся нетронутой. Автотесты не подтверждают функциональную доступность видео/голоса и не заменяют выпускную матрицу задачи 12.

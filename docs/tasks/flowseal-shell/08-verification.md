## Поведение

Отдельная вкладка Game Filter загружает настройки по явной кнопке «Прочитать настройки». Обычная инспекция поставки и обновление состояния по-прежнему не исполняют BAT. Проверенный `service.bat` и безопасные ASCII-настройки копируются под блокировкой чтения в отдельную временную папку; там вызывается только штатный внешний `load_game_filter`. Ни меню, ни внутренние labels не используются как CLI. Из того же CMD экспортируются mode, сохранённые диапазоны и фактические значения TCP/UDP. Системная служба, драйвер, списки и TCP при этом не изменяются.

Редактор показывает отключённый режим, TCP+UDP, TCP и UDP, отдельные диапазоны обоих протоколов. Удаляются только обычные пробелы; принимаются порты 1–65535 и возрастающие диапазоны через запятую без ведущих нулей. Пустые значения, другие символы и неправильные границы отвергаются до записи. Штатный helper независимо проверяет кандидат до записи. Старые флаги, отсутствующий/пустой файл, регистр, повторные ключи и fallback некорректных существующих диапазонов интерпретирует сам Flowseal.

Сохранение пишет `mode=...`, `tcp=...`, `udp=...` в ASCII без BOM с CRLF и завершающим переводом строки. Затем фактические байты перечитываются и снова передаются штатному helper. Сохранение и применение разделены: работающий процесс не изменён; для новых аргументов нужен новый пробный запуск либо переустановка автозапуска. Обычная остановка/запуск зарегистрированной службы её аргументы не обновляет.

Ревизия различает отсутствие файла и SHA-256 его байтов. Перед изменением файл открывается эксклюзивно: сравнение, запись, перечитывание и возможный возврат проходят под одним handle, исключающим сторонние запись/замену. Для отсутствующего файла применяется CreateNew. Общий mutex исключает одновременную операцию оболочки; незавершённый журнал запрещает сохранение. Настройки не требуют изменения или подтверждения принадлежности общей службы, поскольку сохраняются только в выбранной проверенной поставке.

При конфликте файл не меняется, черновик остаётся. Повторное чтение показывает внешние настройки отдельно, сохраняет черновик и обновляет ревизию; затем пользователь может сохранить свои значения поверх показанных или отменить правки. Смена поставки и закрытие учитывают несохранённый Game Filter.

Перед перезаписью существующего файла создаётся уникальная durable `.bak` с исходными байтами. При обрабатываемом отказе записи/flush/helper прежние байты возвращаются с flush под той же блокировкой. При неудаче возврата сообщение указывает backup. Если файл прежде отсутствовал, возврат оставляет пустой файл: штатные disabled/defaults сохраняются, пользователь видит это объяснение. Аварийное завершение GUI/ОС посреди записи настроек не восстанавливается автоматически: backup остаётся для ручного возврата; журнал задачи 07 предназначен для операций службы, а не транзакций редактора.

## Автоматические проверки

Согласованная граница — GUI → IFlowsealAdapter; SCM, драйвер, реальный winws, TCP и HKLM рабочего компьютера не изменяются. Чтение/сохранение проверяется настоящим CMD helper в одноразовых копиях pinned fixture, сбой post-save helper вводится через ICommandRunner (граница процесса).

- TDD: первый адаптерный сценарий упал на отсутствующих API; после реализации прошёл. GUI-сценарий упал на отсутствующих командах/свойствах; после реализации прошёл.
- Матрица чтения/записи: absent, empty, legacy all/tcp/udp, четыре режима, регистр, дубликаты, fallback, независимые диапазоны, 1/65535, пробелы. Диапазон из 360 портов (1079 символов) читается и сохраняется без произвольного ограничения 1024. Файл с множеством штатно игнорируемых комментариев также не ограничивается собственным пределом размера.
- Ошибки обоих диапазонов, CMD-символы, внешняя правка и удаление не меняют файл. Сбой helper после фактической записи возвращает прежние существовавшие/отсутствовавшие настройки.
- GUI: загрузка, нормализация/сохранение, сообщение о неприменённом процессе, сохранение черновика при конфликте, сравнение с внешней правкой, запрет смены поставки и отмена к последнему чтению.

- Сборка `dotnet build Zapret.sln -m:1 -p:UseSharedCompilation=false --no-restore -v:q` прошла без ошибок. NU1900 связан с недоступным NuGet audit, не с ошибкой сборки.
- Core: `dotnet run --project tests/Zapret.Core.Tests --no-build` — 20/20 вне sandbox; внутри sandbox блокировалась существующая проверка атомарной замены временного списка.
- WPF: `dotnet run --project tests/Zapret.Gui.Smoke --no-build -- artifacts/08-light.png --game-filter` и аналогично `artifacts/08-dark-small.png --game-filter --dark --small` — все сценарии, три вкладки, bindings, контраст и layout прошли. Изображения просмотрены; поля, пояснения и кнопки читаются, доступны прокруткой, перекрытий нет.

Чтобы не оставлять хвост общего набора непроверенным, последовательно выполнены `--interrupted-only` и `--guards-only`; оба прошли с кодом 0. Последний флаг только пропускает уже выполненные группы и запускает существующие защитные проверки; обычный полный запуск ничего не пропускает. Все группы проверены, но это не заменяет зелёный единый полный запуск.

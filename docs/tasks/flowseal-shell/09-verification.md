## Поведение

Во вкладке списков показаны «Мои сайты», «Мои исключения», штатные сайты/исключения и дополнительные списки. Назначение объясняется обычным текстом; технический путь и полный текст доступны в расширенном режиме. Добавление принимает домен без схемы/пути, поддерживает IDN, регистр и завершающую точку. Unicode и punycode одного домена не создают дубликат, исходные строки и переводы строк сохраняются.

Связь списка с выбранной стратегией определяется адаптером через статический разбор подтверждённого исходного BAT. Используемый, неиспользуемый список и неизвестная связь различаются явно. Это связь с выбранной конфигурацией следующего запуска, а не утверждение о реально работающем процессе. Изменение выбора и обновление поставки перечитывают эту связь, сохраняя черновик.

Отсутствующие `list-general-user.txt` и `list-exclude-user.txt` видны сразу. Чтение возвращает штатное начальное содержимое в памяти, ничего не создавая на диске. Первое сохранение применяет CreateNew, штатное содержимое и добавленный домен. Начальные строки переиспользуются из одного контракта с подготовкой задачи 04; их соответствие `load_user_lists` проверяется существующим CMD parity. Другие отсутствующие файлы не создаются.

GUI читает, сохраняет и экспортирует списки через IFlowsealAdapter. Сохранение заново проверяет исходный service.bat, папку lists, допустимое имя list*.txt, отсутствие ссылок и незавершённого журнала. Общий mutex исключает параллельную операцию оболочки. Ревизия различает отсутствие и SHA-256 исходных байтов; существующий файл держится эксклюзивно во время сравнения, backup, записи, перечитывания и возможного возврата. Обнаруженные внешние правки/удаления/появление файла не перезаписываются.

Поддерживаются UTF-8 без BOM/с BOM и Unicode UTF-16/UTF-32 с BOM. Кодировка и BOM сохраняются, backup содержит точные прежние байты. Нераспознаваемая кодировка отвергается без потери файла. При обрабатываемом отказе возвращаются прежние байты; для первоначально отсутствующего файла — штатное начальное содержимое Flowseal, с объяснением пользователю. Авария GUI/ОС посреди записи не восстанавливается автоматически: существовавший файл имеет `.bak`; журнал операции службы не является журналом редактора.

Конфликт сохраняет полный черновик и поле домена. «Перечитать для сравнения» показывает внешний текст отдельно и не разрешает обычному сохранению незаметно затереть его. Есть явная замена черновика прочитанным и явное сохранение своих правок поверх показанной версии с повторной проверкой её ревизии. Экспорт пишет новый UTF-8 файл вне поставки через CreateNew, сохраняет редактор и файл поставки. Смена поставки и закрытие учитывают также ещё не добавленный домен.

Сохранение не запускает службу/стратегию. Постоянное сообщение объясняет новый запуск для применения и предупреждает о неиспользуемом списке. Служба, драйвер, TCP и HKLM рабочего компьютера в проверках не изменяются.

- TDD: первый сценарий упал на отсутствующих свойствах редактора; затем добавление IDN в отсутствующий пользовательский файл прошло. Следующий сценарий упал на отсутствующем явном разрешении конфликта; после реализации прошёл. Отдельный красный тест показал Unicode/punycode-дубликат; исправлено.
- Полный графический путь: сайт/исключение, недопустимый URL, конфликт, отдельный экспорт, сохранение объединённого черновика, backup, запрет смены поставки с правками. Адаптер проверяет UTF-8/Unicode с BOM, точные backup-байты, неизвестную/неиспользуемую стратегию и read-only отказ записи.
- По Standards review добавлен красный сценарий ошибки кодирования после создания файла. После исправления оставляется точное штатное начальное содержимое вместо пустого файла; полный WPF повтор прошёл.
- Визуальная проверка выявила не обновлявшуюся доступность кнопки перечитывания. Новый WPF-тест сначала упал на фактическом IsEnabled после загрузки; после добавления CanExecuteChanged для новых команд прошёл. Раскрытый редактор проверяется после завершения анимации темы, включая фактическую высоту текстового поля.
- Сборка solution прошла с `-m:1 -p:UseSharedCompilation=false --no-restore -v:q`. NU1900 сообщает о недоступном NuGet audit. Core — 20/20 вне sandbox.
- Полный WPF smoke прошёл: прежние GUI-сценарии, Game Filter, новые списки, три вкладки, bindings, контраст и layout. `artifacts/09-light.png`, `artifacts/09-dark-small.png`, `artifacts/09-advanced-small.png` используют отдельную временную поставку `.scratch/09-preview`, чтобы показать открытые «Мои сайты» в обычном и расширенном режиме. Настоящая поставка не менялась.

Полный `dotnet run --project tests/Zapret.Guard.Tests --no-build` запускался вне sandbox. Прошли Game Filter, точные штатные seeds, подготовка, все 44 CMD-сравнения стратегий, замена/восстановление службы, управление и модельные пробные сеансы. Изображения проверены: основная форма показывает назначение, связь со стратегией и добавление домена; в минимальном окне прокруткой доступны отдельный экспорт, перечитывание, расширенный редактор, технический путь и кнопки сохранения/отмены. Перекрытий нет. Для повторяемого зелёного полного набора и настоящего применения списков остаётся нужна выделенная Windows; готовность функционального обхода этими тестами не доказана.

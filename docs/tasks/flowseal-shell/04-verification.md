# Задача 04: подготовка Flowseal 1.10.3

Реализация разрешена пользователем 17 октября 2026 года. Основание — задача 04, исходные файлы закреплённой 1.10.3 и задача 03 (`96a6a04`). Работа продолжается в текущей ветке `codex/03-service-recovery-current`; незавершённая приёмка задачи 03 на VM сохраняется.

## Поведение

Предварительная проверка и чтение состояния остаются без выполнения BAT и изменения TCP/списков. После подтверждения принадлежности, стратегии, файлов и полного снимка службы адаптер под общей блокировкой:

1. Берёт проверенный снимок исходного `service.bat` и ASCII-настроек Game Filter. Исходники и существующий флаг открываются без разрешения записи/удаления. Во временной папке исполняется только `load_game_filter`; отсутствующий флаг представлен пустым, что для 1.10.3 эквивалентно disabled. Временные файлы также защищены от записи. Изменения исходных файлов проверяются повторно.
2. В одном CMD выполняет CALL и экспорт трёх переменных `GameFilter`, `GameFilterTCP`, `GameFilterUDP`. Унаследованные значения очищаются. Выходной код отдельной подпрограммы не является доказательством результата: пустой/отсутствующий флаг может оставить ненулевой errorlevel. Проверяется полный экспорт. Старый независимый `ReadGameFilter` удалён; предварительный парсер проверяет статические ссылки с заглушками портов, реальная команда строится из экспортированных значений.
3. Создаёт только отсутствующие `ipset-exclude-user.txt`, `list-general-user.txt`, `list-exclude-user.txt` с точными ASCII/CRLF-данными Flowseal. Используется CreateNew, чтобы не перезаписать появившийся извне файл. Пустые, BOM и изменённые пользователем списки сохраняются. Собственные изменения включаются в ожидаемый отпечаток файлов.
4. Через абсолютный путь `netsh.exe` выполняет `interface tcp set global timestamps=enabled`. Прямое идемпотентное включение заменяет локализованный поиск текста `timestamps/enabled` из `tcp_enable`; ненулевой код блокирует изменение службы. Чтение состояния не вызывает `status_zapret`, поскольку исходная команда сама меняет TCP.
5. Ещё раз проверяет состояние/файлы, затем использует замену и восстановление задачи 03. Маркер стратегии совпадает с Flowseal: имя файла без `.bat`.

Ошибка подготовки не запускает остановку/удаление службы. Созданные списки сохраняются, уже включённые TCP timestamps не откатываются — это явный возможный побочный эффект подготовки. При внешнем изменении автоматические действия прекращаются.

Исходный BAT интерпретирует содержимое настройки через CMD. Поэтому перед выполнением отклоняются ссылки, BOM, не-ASCII и управляющие символы CMD; безопасные неизвестные режимы и ошибочные числовые диапазоны остаются на обработку самой 1.10.3. Проверенный временный снимок исключает подмену содержимого между проверкой и чтением CMD. `/d` отключает Autorun; PATH и текущая папка ограничены системными инструментами и временным снимком. `ProcessRunner` передаёт фиксированный хвост `/c` с правилами кавычек CMD, остальные программы — через ArgumentList.

## Автоматическая проверка

Основная граница — настоящий `IFlowsealAdapter`; Windows-служба и TCP представлены моделями. EXE/bin в fixtures — инертный текст. Реальные BAT-вызовы ограничены двумя подготовительными командами в одноразовых папках. Обновления, диагностика, интерактивное меню, winws и настоящие службы не запускаются.

- Сценарии Game Filter: отсутствие/пустота, all/tcp/udp, mode и регистр, отдельные диапазоны, 1 и 65535, нулевые/слишком большие/обратные/с ведущими нулями/сломанные диапазоны, пробелы, комментарии, повторные ключи и неизвестные режимы. Проверяются фактические аргументы установленной модели службы.
- Создание списков сравнивается побайтово с реальным `load_user_lists`. Проверяются неизменность существующих списков, отказ TCP, неполный экспорт, тайм-аут и внешнее изменение во время подготовки.
- Для всех 22 стратегий исходный блок `service_install` вычисляет аргументы; вместо `sc.exe` их принимает инертный capture-процесс тестового проекта. Порядок и повторные параметры сохраняются; нормализуются только эквивалентные формы `--option value` / `--option=value` и корень пути. Проверяются выключенный фильтр и отдельные TCP/UDP-диапазоны.

Длинный sandbox TEMP вызывает усечение исходного CMD-алгоритма из-за лимита 8191 символа. Для проверки алгоритма `%~dp0` в эталонном блоке заменён общим коротким логическим корнем `C:\Zapret parity\`, а соответствующий префикс команды адаптера приведён к тому же значению. Управляющая логика блока не меняется. Такая проверка доказывает смысл параметров и ссылок, но не подтверждает реальные длинные пути, поведение SCM или работу обхода.

## Обязательная приёмка на VM

Остаётся непройденной: настоящая установка/замена и восстановление задачи 03, чтение исходного значения TCP timestamps, включение и проверка нового значения, возврат исходного TCP-состояния после теста. Для штатного BAT и GUI использовать одинаковые копии поставки/настроек; сравнить ImagePath, параметры, маркер, списки и состояние службы для всех 22 стратегий. Отдельно проверить отказ netsh до остановки прежней службы, длинные пути и пределы CMD/SCM. Прогоны выполнять только в выделенной Windows с восстановлением состояния. Проверки на рабочем компьютере не изменяли настоящую службу и TCP.
